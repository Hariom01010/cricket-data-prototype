CricketData.org API Mapping Specification

Detailed technical breakdown of every CricketData.org API endpoint required to resolve, schedule, and settle prediction questions defined in predictions-api-endpoints.yaml.

01

CricketData.org Endpoints Used in Our Platform

The 4 specific CricAPI v1 endpoints that power the prediction question lifecycle.

GET https://api.cricapi.com/v1/matches

1. Matches List (Fixture Schedule)

Returns all upcoming fixtures with exact scheduled start times, match types, venues, and competing teams.

Used For: Question Generation & Scheduling (T - 24h to T - 2h)
Key Payload Fields Extracted:
  • id (UUID): Used as matchId in our OpenAPI schema.
  • dateTimeGMT (ISO 8601 UTC): Schedules publish time & calculates locksAt.
  • teams (String[]): Fills {{teamA}}, {{teamB}} and generates MATCH_TEAMS options.
  • venue (String): Resolves stadium name placeholder.
  • matchType (String): Validates template applicability (t20, odi, test).

GET https://api.cricapi.com/v1/match_squad?id={id}

2. Match Squad (Lineups & Playing XI)

Returns squads and confirmed playing XI for both teams when released (typically 30–60 mins before kickoff).

Used For: Player Questions (MOST_RUNS, MOST_WICKETS, PLAYER_OF_MATCH)
Key Payload Fields Extracted:
  • data[].teamName: Maps players to corresponding team.
  • players[].id: Converted to our unique option id (e.g. player_123).
  • players[].name: Question option label shown to user.
  • players[].role: Categorizes Batter / Bowler / Wicketkeeper / Allrounder.

  "data": [

GET https://api.cricapi.com/v1/match_info?id={id}

3. Match Info (Toss & Outcome Details)

Provides real-time toss results during pre-match, and official match winner / player of the match after completion.

Used For: Evaluating & Settling Toss & Outcome Predictions
Key Payload Fields Extracted:
  • tossWinner: Team name winning the toss (Settles TOSS_WINNER).
  • tossChoice: Decision ("bat" / "bowl") (Settles TOSS_DECISION).
  • matchWinner: Winning team name (Settles MATCH_WINNER).
  • playerOfMatch: Name of player (Settles PLAYER_OF_MATCH).
View Sample Response Payload 
{
  "status": "success",
  "data": {
    "id": "b2f8e431-c912-48a6-8149-5f21f73b6411",
    "name": "India vs Australia",
    "tossWinner": "India",
    "tossChoice": "bat",
    "matchWinner": "India",
    "playerOfMatch": "Virat Kohli"
  }
}
GET https://api.cricapi.com/v1/match_scorecard?id={id}

4. Match Scorecard (Innings Stats)

Detailed scorecard providing per-player runs, wickets, team boundaries (sixes), and completed overs.

Used For: Evaluating Stats Predictions (Runs, Wickets, Sixes, Final Over)
Key Payload Fields Extracted:
  • scorecard[].batting[].r: Runs scored (Settles MOST_RUNS).
  • scorecard[].bowling[].w: Wickets taken (Settles MOST_WICKETS).
  • scorecard[].batting[].6s: Sum of 6s per team (Settles MOST_SIXES_TEAM).
  • scorecard[].inning / overs: Settles FINAL_SCHEDULED_OVER.

03

Automated Lifecycle & Settlement Pipeline

How the platform transitions predictions from Draft to Published to Resolved.

Stage 1

T - 24 Hours

Call /matches. Identify upcoming fixtures and automatically generate draft questions for MATCH_WINNER and TOSS_WINNER.

Stage 2

T - 30 Mins (Toss)

Call /match_squad to get confirmed Playing XI. Publish player-specific questions (MOST_RUNS, MOST_WICKETS). Automatically lock TOSS_WINNER & TOSS_DECISION.

Stage 3

T - 0 (Kickoff)

Automatically lock all remaining match questions. Prevent new user prediction submissions.

Stage 4

Post-Match Settlement

Call /match_info & /match_scorecard. Compare user answers with winner, runs, wickets, and compute leaderboard points automatically.
